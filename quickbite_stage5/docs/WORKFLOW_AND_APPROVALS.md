# QuickBite — Mandatory Five-Stage Workflow

This workflow is mandatory. Developer and Goldfish operate throughout; Goldfish is not a replacement for any stage.

## Stage 1 — Architect
Developer:
- Inspect available project files and requirements.
- Understand architecture, functionality, database, backend and dependencies.
- Identify preserved functionality, risks and implementation plan.

Goldfish:
- Identify missing journeys and personas.
- Identify usability, accessibility and test needs.

**No coding.**

## Stage 2 — Critical Reviewer
Developer/reviewer:
- Challenge architecture, assumptions, security, integrity, performance and maintainability.

Goldfish:
- Independently challenge customer journeys, feedback, validation, errors and usability.

**No coding.**

## Stage 3 — Improvement
- Incorporate valid criticism.
- Resolve weaknesses.
- Consolidate architecture.
- Define requirements, acceptance criteria and test cases.

**No coding.**

## Stage 4 — Approval
Present a detailed implementation plan including:
- Unique requirement IDs.
- Files/modules affected.
- UI/UX specification.
- Database/backend changes.
- Security considerations.
- Goldfish criteria.
- Acceptance evidence.
- Tests, risks and unresolved questions.

**Wait for explicit user approval. No coding.**

## Stage 5 — Implementation
Only after explicit Stage 4 approval:
- Implement approved scope.
- Preserve architecture and existing approved requirements.
- Verify syntax and functionality.
- Goldfish independently inspects actual evidence.
- Fixes return to Developer; Goldfish retests without editing source.

## Approval interpretation
- A request to create or update documentation is not implementation approval.
- “Not approved” means approval is withheld.
- Silence or ambiguous wording is not approval.
- Approval applies only to the clearly identified plan/version.
- Scope changes require review, user approval and changelog entry.

## Stage records
At each stage completion/approval:
1. Update this file's stage status.
2. Update impacted specifications.
3. Record decisions and open items.
4. Append a dated changelog entry.
5. Preserve the prior history; do not erase earlier decisions.
